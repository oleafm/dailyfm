# Tasks

Task details and task creation open in a floating right-hand drawer, accessed from the parent project or an existing Today task. The background stays in place. A `task` URL parameter restores the drawer on reload; legacy `/tasks/{id}` links open it over the parent project. Closing returns to the same background context. There is no Tasks navigation tab or global task index; `/tasks` redirects to Projects. The checkbox still completes/reopens the task directly.

Project task lists show 10 items initially, with a View more action to reveal the rest. Today’s intention list shows only open, unarchived tasks, with five initially and a View more action. Completing a task removes it from intentions and adds its completion to today’s recent activity; completed task titles there open the detail drawer. Session logs show three initially, with View all logs to reveal the rest. The drawer uses one column: top actions (Mark done / Reopen, Archive / Restore, Status), focus controls, compact statistics, task name and description, notes, and session logs.

Project pages show two columns: project tasks on the left, with a black “Add a Task” action and Open / Done / Archived filters; today’s completed tasks for that project on the right, including completion time and all-time tracked task duration in place of the area tag. The completion feed excludes other dates, other projects, reopened tasks, and legacy milestone events. The columns stack on mobile. Milestone controls are removed; existing milestone data is retained. Starting focus from a project keeps the user on that project, including when another timer needs attention.

A task has a title, optional description, To do / In progress / Done status, and a stream of dated progress notes. Notes can be edited and deleted, with confirmation before deletion. Existing project links are displayed, but there are no project assignment or move controls on the task page. Existing creation flows are preserved.

The task page shows all saved sessions linked by `taskId`, across all dates: total focused time, session count, days with saved focus, exact start/end times, individual focused duration, and session notes. Totals sum saved session durations once; the mirrored activity records are not counted again. Pauses are excluded. An active session is displayed separately until saved. Historical sessions without end timestamps say “End time not recorded”.

Start focus links a timer to the task and marks it In progress. Finish pauses every timer and opens a compact review. Saving adds a new time entry to the task or project and leaves the task open (In progress). The review shows the descriptive Do/Be area toggle, Category, an optional Project selector for either area, “Create new project” directly below it, and then “What did you focus on?”. Projects are filtered by the selected area; changing area clears stale project/task assignments. Task selection, task creation, and notes live under Add details. New projects inherit the selected area. The new-project dialog uses the same toggle and defaults to the current home area, as does an unassigned timer review; assigned timer reviews preserve the task or project area. The summary retains its original padding and a 156px minimum height. Project pages offer Start project focus; the project context is stored in the device-local timer, including across pause/reload. Closing the review keeps the paused timer; reopening preserves its captured end time. Edit accepts hh:mm:ss within the recorded time window, keeping original timestamps intact. Corrected sessions retain originalDurationSeconds and durationAdjusted metadata, and activity totals use the corrected focused duration. Reset asks for confirmation and discards only the unsaved session, without completing tasks or changing earlier logs. Completing a task from any task control automatically stops and saves its active timer, including a paused timer, and completes the task in one workspace update. Completing a different task leaves the running timer alone. Repeated completion does not duplicate the saved session. Reopening preserves recorded time and notes. The existing one-running-timer rule still applies.

A session’s note or task assignment can be corrected from its history entry. This updates the saved session and matching activity record together, keeping the original duration and timestamps. Project attribution follows the target task’s existing link; the task itself is never moved.

Archiving hides tasks from active lists while retaining their sessions, descriptions, and notes. Archived tasks can be viewed and restored from the parent project’s Archived filter. An active task must have its session finished before archiving. Task deletion is not offered.

## Storage

`Project` stores an optional `area` in its existing owner-scoped payload; legacy projects default to Do. The sidebar and project overview filter projects by the active Do/Be area, and project task creation inherits that area. No database migration is required.

`Task` extends the existing owner-scoped `daily_tasks.payload` with optional `description`, `status`, `notes`, and `archivedAt`. Each note contains `id`, `text`, `createdAt`, and optional `updatedAt`. The existing `completed` field stays synchronized for compatibility. Legacy tasks without new fields remain usable. All fields inherit the parent task’s per-user row-level security; no additional database migration or service credentials are required.

Workspace account autosave, local pending-change recovery, and revision-conflict handling apply to edits, notes, session corrections, and automatic completion. Running timers remain device-local. This does not add realtime synchronization between devices.

## Validation

`npm run test:projects` verifies area filtering, legacy Do defaults, Be project/task/session creation, and rejection of cross-area project assignments. `npm run test:tasks` verifies focused-time totals, automatic completion, paused timers, repeated Done, reopening, unrelated timers, session corrections, and legacy status handling. `npm run test:security` verifies rich task payloads round-trip through the real PostgreSQL-compatible test database and cannot be read or changed by another owner. Browser checks cover task creation, deep-link reloads, descriptions, note editing/deletion, automatic completion, standalone task sessions, archive/restore, and desktop/mobile layouts.
